# Отличия от эталона

Эталон — uniland 2.2.0 на Python, лежит рядом в каталоге `../uniland`.
Задача этого репозитория — вести себя так же, поэтому всё, что удаётся
повторить, повторяется буква в букву, а отличия собраны здесь.

## Как проверяется совместимость

Скрипт `compat/runner.py` запускает эталон на кейсах из `compat/cases` и
складывает stdout, stderr и код возврата в `compat/expected`. Скрипт
`compat/tokens.py` снимает дампы лексера в `compat/expected-tokens`.
Тесты `go test ./...` сверяют с этими файлами наш бинарник, Python для
самих тестов не нужен.

Снимки не редактируются вручную: если поведение должно измениться,
перегенерируйте их эталоном.

## Что совпадает

CLI повторяет cli.py: приоритет режимов `-c` больше `-e`, `-e` больше `-i`,
`-i` больше подкоманды, без аргументов открывается REPL. Сообщения
`UniLand error: ...` и `Error at line N: ...`, коды возврата, вывод `-d`,
баннер и подсказки REPL, счёт скобок для многострочного ввода — всё
сверено снимками.

Тексты ошибок тоже эталонные: `X() expects N argument(s), got M`,
`Undefined variable: X`, `Cannot reassign constant: X`,
`List index N out of range`, `pop() from empty array` и остальные.
Квирк с лямбдами семейства `is_*` сохранён: эталон строит проверки через
`_is(lambda ...)`, поэтому в сообщении стоит `<lambda>()`.

Блоки `python { }`, функции `pyeval`, `pyexec`, `py` и объект `uni`
работают как в эталоне: пространство имён Python живёт между блоками,
вывод печатается в порядке исполнения, значения ходят в обе стороны.
Большие целые (`2 ^ 100`, `2 ** 100`) не теряют точность, JSON сохраняет
порядок ключей, `Infinity` и `NaN` поддерживаются.

`try/catch/finally` ловит только `UniLandError`, `finally` выполняется на
любом пути, включая `return`, `break` и `continue` из блока `try`.

## Отличия

1. `-h` печатает справку, близкую к argparse, но переносы строк и ширина
   могут отличаться. Строка usage и коды возврата совпадают.

2. Ctrl+C в REPL. Эталон печатает `^C` и продолжает работу, в Go сигнал
   не прерывает чтение stdin так же просто, поэтому процесс обычно
   завершается сразу, и код возврата может отличаться от 130.

3. `break`, `continue` и `return` вне цикла или функции. Эталон падает с
   трассировкой Python, у нас печатается `UniLand error: break вне цикла`
   и код 1. Вывод до ошибки совпадает.

4. Исключения Python, не являющиеся `UniLandError`, эталон выпускает
   наружу с трассировкой, у нас они превращаются в `UniLandError` с тем
   же текстом сообщения.

5. Тексты ошибок файловых операций на Windows приводятся к виду Python:
   `No such file or directory`. Номера errno в редких случаях отличаются.

6. `list_dir` сортирует имена, потому что `os.ReadDir` в Go сортирует, а
   `os.listdir` в Python — нет. Содержимое совпадает, порядок может
   отличаться.

7. `system()` читает вывод дочернего процесса как есть. Эталон декодирует
   его в кодировке локали Windows, для русской машины это cp1251. Для
   UTF-8 команд разницы нет.

8. `http_*` работает на `net/http`, а не на `requests`. Тело JSON
   кодируется с `ensure_ascii=False`, тексты сетевых ошибок свои.
   Проверки вида «need the 'requests' package» не воспроизводятся, потому
   что пакет не нужен.

9. Ошибка сериализации JSON: текст `Object of type X is not JSON
   serializable` строится приблизительно, по типу значения.

10. Архивы: в путях внутри архива используется `/`. Эталон на Windows
    кладёт `os.sep`, то есть обратную косую черту. `unzip` понимает zip,
    tar и tgz, тексты ошибок формата отличаются от `shutil`.

11. `open_file` и `open_url` вызывают те же программы Windows, что и
    эталон (`rundll32`, `cmd`), но напрямую, без `os.startfile`.

12. REPL и `input()` читают один буфер, как `sys.stdin` в Python, поэтому
    между двумя вызовами `input()` ничего не теряется.

13. `exit(код)` приводит строку, число и bool к целому так же, как
    эталон. Строка, которая не приводится, даёт `UniLandError`.

## Байткод-машина

Скрипты исполняет `internal/vm`: код компилируется в инструкции и
выполняется кадрами. Арифметика, индексация, вызовы и тексты ошибок не
переписаны — машина вызывает те же функции, что интерпретатор по дереву,
поэтому сообщения совпадают по построению.

Интерпретатор по дереву остался эталоном поведения и включается
переменной `UNILAND_TREEWALK=1`. Тест `internal/core/parity_test.go`
исполняет каждый golden-кейс, весь корпус `compat/vmcases` и сценарии
REPL обоими движками и сравнивает stdout, stderr и код возврата побайтно.
Кейс корпуса обязан разбираться парсером: иначе оба движка падали бы на
одной и той же синтаксической ошибке, и проверка ничего бы не значила.

Корпус `compat/vmcases` содержит 24 файла: замыкания, циклы, шаблоны,
протокол `try/finally` и сигналы, большие числа, мосты в Python и Go,
встроенные функции.

Найденные расхождения закреплены отдельными кейсами:

- `v18_compound_order.uni` — `o.s += "b"` давало `"ba"`, потому что
  значение из регистра возвращалось на стек после правой части, и
  некоммутативная операция считалась в обратном порядке;

- `v19_try_rethrow.uni` — `throw` из `catch` вылетал из кадра и не
  доходил до внешнего `try`, внешние `finally` при этом терялись.

Ограничения текущей версии машины: кадр использует именованные
окружения, а не слоты, JIT и оптимизаций нет. Цель этапа — равенство
поведения, а не скорость.

## Блоки go

В эталоне блоков `go { }` нет, это расширение. Код исполняется через
yaegi. Без импортов доступны `fmt`, `strings`, `strconv`, `math`, `sort`,
`time`, `math/big`, `unicode`, `regexp`.

Каждый блок получает свежее окружение Go, а обмен значениями идёт через
объект `uni`: `GetInt`, `SetInt`, `GetFloat`, `SetFloat`, `GetStr`,
`SetStr`, `GetBool`, `SetBool`, `GetBig`, `SetBig`, `Call`, `CallJSON`.
Метод `Call` приводит строковые аргументы как Python: `"7"` становится
числом, `"true"` — булевым, остальное остаётся строкой. Обратно значения
возвращаются строкой. Для доступа к Python из Go есть `uni.PyEval*` и
`uni.PyExec`.

Ошибки в `uni.*` поднимаются как panic с текстом Python, yaegi
превращает их в ошибку `Go error: ...`. Функция `goeval` считает
выражение и переводит результат в значение UniLand: числа, строки, bool,
`*big.Int`, остальное печатается через `%v`.

Контракт зафиксирован кейсом `compat/cases/t11_golang.uni` и снимком,
написанным вручную, потому что эталон этот код не исполняет.

## Python-мост

Интерпретатор ищет Python в порядке: `UNILAND_PYTHON`, затем `python3`,
затем `python`. Каждый кандидат проверяется запуском `-c print(1)`,
заглушки Microsoft Store отбрасываются, проверка ограничена пятью
секундами.

Работает отдельный процесс `pyworker.py`, обмен идёт строками JSON по
stdout и stdin. Операции: `exec`, `eval`, `shutdown`, плюс запросы
`uni_get`, `uni_set`, `uni_call` из Python в интерпретатор. Вывод
Python-кода перехватывается и печатается в порядке исполнения. Значения
передаются конвертами вида `{"T": ...}`, большие целые — строкой, объекты
— списком ключей, чтобы сохранить порядок.

## Окна

Функций `gui_*` в эталоне нет. В обычной сборке они всегда есть в
реестре и возвращают ошибку `GUI недоступен в этой сборке: пересобери с
-tags fyne`, которую можно поймать через `try/catch`. Сборка с тегом
`fyne` открывает настоящие окна и требует cgo: на Windows mingw-w64, на
Linux gcc и xorg-dev.

Доступны `gui_window`, `gui_alert`, `gui_ask`, `gui_confirm`. Окно
принимает список элементов: `label`, `entry`, `check`, `button`,
`separator`. Значения собираются по полю `key`: из `entry` приходит
строка, из `check` — bool. Вызов блокирует скрипт до закрытия окна.
Контракт зафиксирован кейсом `compat/cases/t12_gui.uni`.

## Форматтер и LSP

`uniland fmt` работает по исходному тексту, а не по дереву разбора,
потому что лексер отбрасывает комментарии. Меняются только отступы
(четыре пробела на уровень фигурных скобок), хвостовые пробелы и пустые
строки. Тела `python { }` и `go { }` не трогаются: Python чувствителен к
отступам.

Тесты `internal/unifmt` проверяют три свойства: поток токенов до и после
форматирования совпадает, повторное форматирование ничего не меняет, а
отформатированные файлы корпуса дают тот же вывод при запуске.

`uniland lsp` говорит по stdio на JSON-RPC. Синхронизация документа
полная, форматирование отдаётся одним исправлением на весь файл.
Диагностика — одна ошибка лексера или парсера, позиция берётся из
`unierr.Error.Line`.

Обе подкоманды разбираются до основного разбора аргументов, поэтому
строка usage и коды возврата argparse не изменились.

## Примечания к грамматике

Формальная грамматика лежит в `docs/grammar/uniland.ebnf`. Несколько
правил, которые легко упустить:

1. Инструкция заканчивается переводом строки или точкой с запятой.
   Перевод строки не завершает инструкцию, если предыдущий значимый
   токен — оператор (кроме `++` и `--`) или одна из скобок `(`, `[`,
   `{`, запятая, точка, двоеточие. Поэтому `let a = 1 +` и `2` на
   следующей строке — одна инструкция.

2. `||` и `&&` имеют одинаковый приоритет и левую ассоциативность:
   `a || b && c` разбирается как `(a || b) && c`. Это поведение эталона,
   менять его нельзя, на нём стоят снимки.

3. `^` тоже левоассоциативен: `2 ^ 3 ^ 2` равно `(2 ^ 3) ^ 2`, то есть
   64.

4. `++` и `--` бывают только постфиксными и только как отдельная
   инструкция. В выражении их нет.

5. Ключ объекта — идентификатор или строка. Числовой литерал в позиции
   ключа даёт ошибку.

6. В шаблонных строках подстановка записывается как `{выражение}`,
   литеральные скобки удваиваются: `{{` и `}}`.

7. Комментарии: `// ...`, `# ...`, `/* ... */`.
