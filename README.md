# UniLand на Go

UniLand — небольшой скриптовый язык: переменные, функции, массивы, объекты,
шаблонные строки, try/catch, плюс встроенные блоки Python и Go прямо в коде.
Этот репозиторий — интерпретатор UniLand, переписанный на Go. На выходе один
бинарник: для запуска скриптов Python не нужен, нужен только там, где скрипт
сам использует `python { }`.

Совместимость с эталонным интерпретатором uniland 2.2.0 проверяется
автоматически: 16 кейсов сравнивают stdout, stderr и код возврата, ещё
15 наборов — дампы токенов лексера.

```
  _   _    _   _    ___    _           _       _   _    ____
 | | | |  | \ | |  |_ _|  | |         / \     | \ | |  |  _ \
 | | | |  |  \| |   | |   | |        / _ \    |  \| |  | | | |
 | |_| |  | |\  |   | |   | |___    / ___ \   | |\  |  | |_| |
  \___/   |_| \_|  |___|  |_____|  /_/   \_\  |_| \_|  |____/
```

```uniland
let name = "мир"
print(`Привет, {name}!`)

func fib(n) {
    if (n < 2) { return n }
    return fib(n - 1) + fib(n - 2)
}

print(fib(10))
```

## Сборка и запуск

Нужен Go 1.23 или новее.

```bash
go build -o uniland .
./uniland -v
./uniland run script.uni
./uniland -e 'print(2 + 2)'
./uniland -i
```

Окна собираются, когда есть C-компилятор и cgo включён. Если компилятора
нет, собирайте с `CGO_ENABLED=0` или `-tags nogui`: тогда `gui_*`
возвращают ошибку, которую можно поймать. Принудительно без окон:
`go build -tags nogui -o uniland .`

Пошаговая установка в систему на Windows, Linux (включая Arch) и в Termux
лежит в `docs/install.md`.

Аргументы и коды возврата повторяют эталон: `-c` проверяет синтаксис,
`-e` выполняет строку, `-i` открывает REPL, `run -d` печатает токены.

## Как устроено

```
main.go              разбор аргументов и подкоманды
internal/lexer       лексер, порт lexer.py
internal/parser      парсер, порт parser.py
internal/ast         узлы дерева
internal/interp      дерево-интерпретатор: окружения, вызовы, исключения
internal/vm          байткод-машина: компилятор и исполнение
internal/std         встроенные функции
internal/pyops       арифметика и приведение значений как в Python
internal/pybridge    процесс Python и обмен значениями
internal/gobridge    блоки go { } через yaegi
internal/gui         окна на Fyne
internal/core        связка лексер-парсер-исполнение, REPL
internal/unifmt      форматтер
internal/lsp         Language Server
compat/              снимки эталона и кейсы
examples/            запускаемые примеры из курса, их вывод сверяется тестами
docs/                описание отличий и грамматика
```

Скрипты исполняет байткод-машина. Интерпретатор по дереву остался эталоном
поведения: он включается переменной `UNILAND_TREEWALK=1`, и тесты сверяют
вывод обоих движков побайтно на всех кейсах. Если правка ломает паритет,
падает тест, а не пользовательский скрипт.

## Тесты

```bash
go test -tags nogui ./...
```

Тег `nogui` отключает окна, поэтому C-компилятор для тестов не нужен.
Golden-тесты собирают бинарник с этим же тегом. Полную сборку с окнами
проверяет отдельная джоба CI.

Снимки в `compat/expected` и `compat/expected-tokens` снимаются с эталона
скриптами `compat/runner.py` и `compat/tokens.py`; вручную написаны только
снимки `t11_golang` (эталон не умеет `go { }`) и `t12_gui` (контракт
заглушки). Для пересъёмки нужен Python и клон эталона рядом (`../uniland`).

## Форматтер и LSP

```bash
uniland fmt script.uni        # вывод в stdout
uniland fmt -w script.uni     # перезаписать файл
uniland fmt -l script.uni     # проверить, код 1 если файл не отформатирован
uniland lsp                   # сервер для редактора, обмен по stdio
```

Форматтер меняет только отступы, хвостовые пробелы и пустые строки. Он не
переставляет токены, поэтому комментарии и тела `python { }` и `go { }`
остаются как были. Сервер умеет показывать ошибки лексера и парсера и
форматировать документ.
